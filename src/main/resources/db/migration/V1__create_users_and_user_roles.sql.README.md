# V1__create_users_and_user_roles.sql

## Simple overview
This is the first database migration. It creates the user table and the table that stores each user's roles.

## Key behavior
- Creates `users` with an identity primary key, unique email, required names and password hash, optional date of birth, active flag, and creation timestamp.
- Creates `user_roles` with a composite primary key of `(user_id, role)`.
- Adds a foreign key from `user_roles.user_id` to `users.id` with cascade delete.
- Do not edit this migration after it has been applied; add a new `V2__...sql` migration instead.

## Related files
- `entity/User.java`
- `entity/Role.java`
- `application.properties`

## Deep dive

### Flyway naming and execution
Flyway recognizes files named `V<version>__<description>.sql`. This file is version 1, so Flyway applies it once and records it in the `flyway_schema_history` table.

Flyway runs before Hibernate validation because `spring.flyway.enabled=true` and the application uses `ddl-auto=validate`. The application will not start if the migration fails or if the resulting schema does not match the entities.

### `users` table
The `users` table contains:

- `id`: `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. The database generates the value, matching `GenerationType.IDENTITY` in `User`.
- `first_name`: required, maximum 50 characters.
- `last_name`: required, maximum 50 characters.
- `email`: required, maximum 255 characters, with unique constraint `uk_users_email`.
- `password_hash`: required, maximum 255 characters.
- `date_of_birth`: nullable date.
- `active`: required boolean with a SQL default of `TRUE`.
- `created_at`: required timestamp with time zone. There is no SQL default, so the application must supply the value; the entity does through `Instant.now()`.

The unique email constraint also creates an index that supports email lookups such as `UserRepository.findByEmail`.

### `user_roles` table
The `user_roles` table is the storage for `User.roles`:

- `user_id`: required foreign key to `users.id`.
- `role`: required `VARCHAR(255)` containing the enum name, such as `BUYER`.
- The composite primary key `(user_id, role)` prevents duplicate role assignments.
- `ON DELETE CASCADE` means deleting a user automatically deletes that user's role rows.

There is no separate role table, so the database does not validate role names. Valid values are defined by the Java `Role` enum.

### Why not edit this file
Once a migration has been applied, Flyway checks its checksum. Editing the file after it has run in an environment causes a checksum mismatch and can prevent startup. It also means different environments may have different schemas despite reporting the same version.

For schema changes:

1. Create a new file such as `V2__add_user_status.sql`.
2. Write only the incremental change.
3. Keep it compatible with both PostgreSQL and H2 in PostgreSQL mode.

### Portability
The SQL uses standard identity, timestamp-with-time-zone, boolean, and foreign-key features supported by PostgreSQL and H2's PostgreSQL mode. Avoid PostgreSQL-only types or functions unless both test databases are updated.
